# 9. Verification and Evaluation Plan

The aim is to show that MotionScope detects and tracks moving objects better than a classical baseline and is usable. This plan states what will be measured, on what, under which conditions, and against which baseline. No results exist yet; the baseline code and its tests are the first verified artefact.

## 9.1 Baseline for comparison

**B0 – Classical pipeline** (`src/vision/baseline_mog2.py`): OpenCV MOG2 background subtraction, morphological clean-up, connected components, centroid-based tracking. It has no class labels and no appearance cues.

**Proposed system (P1):** YOLO detector + ByteTrack + displacement-based motion criterion.

Hypotheses (to be confirmed or rejected by measurement):
- H1: P1 achieves higher detection F1 than B0 on videos with lighting change or dynamic background.
- H2: P1 achieves higher IDF1 and fewer ID switches than B0's centroid tracker.
- H3: B0 is faster than P1; P1 meets the throughput target in NFR-01.

## 9.3 Datasets

| Dataset | Use | Notes |
|---|---|---|
| CDnet 2014 [L15] | Motion-detection accuracy of B0 and P1 on selected categories (baseline, dynamic background, night, shadow, bad weather) | Pixel masks; report per category |
| MOT20 / MOTChallenge [L16] | Tracking metrics in crowded scenes (subset) | Check licence and terms before use |
| Own videos | 10 or more clips (30–120 s) of target scenes, labelled with an annotation tool | Static camera; people's faces avoided or consented; labelled by one member, checked by another |
| Synthetic clips | Deterministic unit tests (`tests/`) | Generated by code, no privacy issue |

## 9.4 Metrics

| Aspect | Metric | Definition source |
|---|---|---|
| Motion-detection quality | Recall, Precision, F-measure, PWC | CDnet 2014 metrics [L15] |
| Detection quality | Precision, recall, F1 at IoU 0.5 | Standard |
| Tracking quality | MOTA, IDF1, HOTA, ID switches | [L13], [L14] |
| Speed | Frames per second, end-to-end seconds per minute of video | Measured |
| Resources | Peak RAM, GPU memory | Measured |
| Usability | SUS score, task completion rate, time on task | Standard questionnaire |
| Extraction quality | Share of moving tracks with a valid crop and clip; clip start error in frames | Measured |

For tracking metrics use an established evaluation implementation (for example the TrackEval tool used with MOTChallenge) rather than writing metrics from scratch *(verify availability and licence)*.

## 9.6 Evaluation matrix and decision rules

| Experiment | Dataset / input | Systems compared | Metrics | Decision rule |
|---|---|---|---|---|
| Motion robustness | Selected CDnet 2014 categories | B0 and P1 | Precision, Recall, F-measure, PWC | Report each category separately; explain any category where P1 does not improve on B0. |
| Tracking quality | Licensed MOT20 subset and own labelled clips | B0 centroid tracker and P1 ByteTrack | MOTA, IDF1, HOTA, ID switches | P1 should improve IDF1 and reduce ID switches relative to B0. |
| Throughput | Same 720p test clips on the reference machine | B0 and P1 | FPS and end-to-end seconds per minute of video | Run each configuration at least three times and report the median. |
| Extraction quality | Own labelled clips | P1 | Valid crop and clip rate; clip start error | Each moving track must produce an openable crop; clip padding is measured in frames. |
| Privacy and failure handling | Representative valid, corrupt, and unsupported files | P1 | Network activity, error response, service availability | No external network calls; invalid input fails with a readable reason while the service remains available. |
| Usability | Five or more non-team participants | Web UI | SUS, task completion rate, task time | Compare the result with NFR-04: SUS at least 68 and at least 80% task completion without help. |

All comparisons use the same input video, configuration, and measurement conditions for B0 and P1. The evaluation report will include raw run records or links to versioned result files.

## 9.7 Usability test protocol

- 5 or more participants not on the team; 3 tasks: upload a video and start analysis; find the first moving person and play its clip; export the report.
- Observe without helping; record success, time and problems; then SUS questionnaire.
- Outcome feeds the UI backlog; link evidence in `docs/evidence/`.

## 9.8 Acceptance of the project aim

The aim is considered demonstrated when:
1. All **M** requirements in [06](06-requirements.md) pass their acceptance criteria.
2. The evaluation report shows P1 versus B0 on the metrics above with the conditions in 9.5, and states which hypotheses held.
3. NFR-04 (usability) and NFR-03 (privacy) pass.
4. A second member reproduces the headline metrics (NFR-09).
